# 已知问题

本页记录目前已知、且与 Easel 使用相关的问题，以及推荐的规避方式。遇到未列出的问题，欢迎提交 [Issue](https://github.com/ZJU-REAL/Easel/issues)。

## 扫码确认与当前账号身份校验

- **微信视频号扫码后一直等待**：检测微信扫码组件的确认状态，检查同一浏览器中的跳转页面，并复用辅助页进行低频认证检查，不再频繁创建发布页。手机扫码不等于登录完成；只有已认证的当前视频号接口或可见的登录后界面才判定成功。微信二维码过期时明确提示重新登录。
- **头像或昵称不属于当前账号**：视频号优先读取当前视频号身份接口，页面备用读取限定在视频号账号卡片，避免取到管理员微信头像；抖音优先读取当前账号接口，知乎不使用内容作者头像作为备用。公众号后台会话也校验真实后台账号，单独配置的 AppID 凭证仍仅展示配置名称。
- **成功后校验返回空白身份**：等待扫码浏览器保存并释放登录目录后再校验，避免两个浏览器抢同一目录；更新前的身份缓存不再沿用。
- **视频号校验页面迟迟未就绪**：身份接口单独等待最多 45 秒；页面空白、接口未返回或网络异常属于校验失败，不是已退出登录。保留上次已验证的昵称、头像及登录状态，不缓存新的「未登录」结论；明确出现已加载的登录二维码才作为未登录信号。
- **刷新二维码或网络中断**：重新点击普通平台登录会先退出旧扫码进程，再生成新二维码。前端登录轮询串行执行，状态请求限时，连续连接失败或超过等待预算会结束等待。公众号扫码轮询中的二维码重截只做一次尝试，避免反复等图片拖慢成功检测。
- **仍需人工验证的环节**：每个平台都需要用手机完成扫码及确认；服务器连通性、平台风控和手机号/管理员授权仍可能影响登录。反馈时只提供脱敏状态和错误类型，不公开 Cookie、账号身份、完整登录跳转地址或二维码令牌。

## 小红书 / 知乎二维码登录与 Windows 日志编码

- **点击登录后很久才出现弹窗**：弹窗现在点击即显示启动进度，后台启动接口不再等待二维码生成；页面每秒读取状态，二维码就绪后自动展示。关闭弹窗不会被迟到的接口响应重新打开，平台页面加载和二维码生成仍受网络与平台响应速度影响。
- **小红书校验慢或昵称、头像串号**：同平台并发校验合并为一次；优先检查已认证的创作平台接口，页面备用校验有总时间预算。昵称、头像只读账号区域或「我」链接对应的个人主页，不再搜索信息流中的通用用户节点；无法确认时留空，不以其它用户资料填充。旧版前端账号资料缓存已失效。
- **知乎扫码确认后一直等待、重试仍是旧码**：确认时检查同一浏览器会话的账号接口，并使用与账号选择器匹配的知乎首页作为备用探测页。再次点击登录先退出旧登录进程再获取新码；扫码后不刷新二维码，未扫码的明确过期码可有限刷新。
- **视频号登录等待整页加载超时**：登录导航改为等待页面开始加载，再单独等待登录控件和二维码 iframe；不再因整页 `DOMContentLoaded` 超时直接放弃已有的登录页面。只保存检测到的真实二维码，不再把空白微信组件或整页当二维码；登录成功必须有已认证的当前账号接口或可见的账号标识。仍失败时检查 `channels.weixin.qq.com`、微信脚本 CDN `res.wx.qq.com`、扫码服务 `open.weixin.qq.com` 和扫码轮询 `lp.open.weixin.qq.com`；首页可访问并不代表脚本或二维码图片能加载。不绕过网络或平台限制。
- **Windows 报 `gbk codec can't encode character`**：旧版登录脚本输出 emoji 时可能报错，甚至把已成功的登录误报为失败。新版统一以 UTF-8 输出登录日志，Web 启动登录子进程也显式设置 UTF-8；请更新后重新启动 Web。
- **知乎截图是整个登录界面、二维码很小**：新版识别小尺寸二维码和大小写不同的二维码选择器，实际检测二维码图案、裁剪并放大；找不到二维码会明确报错，不再把整页截图冒充二维码。小红书使用相同截图校验。
- **二维码白边在网页样式中、图片本身没有白边**：截图校验会先补白边，并处理透明背景，避免把可扫码的小图误判为非二维码。
- **小红书提示「未找到可识别的登录二维码」**：新版首页需要先点击登录入口；创作平台默认短信登录，右上角图片图标才是扫码切换入口。已兼容这两个入口及没有 `qrcode` 类名的二维码图片，并等待登录组件加载完成。仍失败时分别报告首页/创作平台的风控、空白页、短信模式或二维码加载问题，避免备用页失败掩盖首页的真实原因。
- **页面换码后 Web 仍显示旧码**：等待登录期间定期重新截图，只有图像变化才原子替换文件并更新缓存键；小红书明确提示二维码失效时，仅点击登录组件内的刷新控件，最多三次，不重载页面或延长二维码有效期。检测到扫码成功后停止刷新，等待 App 确认，避免换码打断确认。
- **小红书扫到无效二维码**：创作平台的扫码切换图标可能也含二维码图案；截图时排除过小的图案，不把切换图标当成登录凭证。已失效的二维码不能继续使用，请关闭登录弹窗重新获取。
- **小红书显示「工程师正在维护」**：维护页与二维码过期、退出登录分开处理；校验尝试首页和创作平台两个入口，网络超时或维护页面不作为可信的退出登录结论。不绕过平台维护和风控，仍需等待平台恢复或检查服务器网络。
- **扫码成功后卡片仍显示未登录**：登录成功立即更新卡片并清除旧缓存；手动校验会绕过服务端缓存。登录前启动的旧校验不能覆盖登录后结果，也不能删除新登录标记；网络/维护异常保留上次已知状态，不声称本次已验证成功。
- **创作平台页面加载慢导致账号校验失败**：优先使用同一持久化浏览器会话请求官方账号接口，只有服务端明确返回成功和账号 ID 才确认登录；接口超时、异常或拒绝时仍检查页面，不把 Cookie 文件存在或缓存账号信息当成登录证据。
- **扫码后页面没有跳转或跳到维护页**：扫码确认期间定期检查同一会话的创作平台账号接口；页面提示异常时也先检查接口，只有明确返回账号身份才完成登录。已经扫码但确认超时会单独提示，不再误报「二维码超时未扫」；真正的维护和网络问题仍需排查。
- **跳转后误报已登录**：知乎要求可见的账号标识；小红书创作平台要求可见且已填充的账号头像和昵称，不再仅凭发布页地址判定登录成功。小红书首页超时也会尝试一次创作平台入口；只有两个入口都明确显示登录界面时才判定已退出，单个入口失败不会覆盖另一入口的未知状态。
- **小红书总提示 IP 风险**：旧版把所有安全限制/错误页都归为 IP 风险；新版区分明确的 `300012` 与其它错误，并在首页无法获取二维码时尝试一次官方创作平台登录入口。
- **平台确实返回 `300012`**：备用入口也可能被限制，代码更新不能保证解除平台风控。先确认目标网站在可信网络可访问；有桌面环境时可用 `xhs_publish.py login --headed --no-proxy` 查看平台原始提示。Web 默认国内平台直连，不自动使用模型代理；不要公开或互相传递 Cookie、浏览器登录目录。
- **反馈仍失败的情况**：请附脱敏的 `outputs/_login/xiaohongshu.log` 或 `zhihu.log`、平台错误码、操作系统与浏览器版本；删除账号信息、Cookie、代理凭证和二维码登录令牌。服务器无法访问平台时，先检查网络连通性，而不是把所有异常都当成 IP 风险。

## CLI 终端对话中「问答题」后回复重复显示

- **影响范围**：仅 `easel chat`（终端对话）。**Web 工作台不受影响**。
- **表现**：当 Agent 触发一次 `ask_user` 问答题、用户回答之后，Agent 的下一条回复在终端里可能被重复渲染一次（内容正确，只是显示了两遍）。
- **性质**：这是**纯显示层**问题，不影响实际对话内容、产物生成或发布结果。

### 根因

问题位于上游 [OpenClaw](https://www.npmjs.com/package/openclaw) 本体的**会话投影（session projection）**逻辑，不在 Easel 仓库内。

`easel chat` 底层调用 `openclaw tui`，由 OpenClaw 的 gateway-client 负责在终端重建对话记录。当一条实时回复与另一行（例如 `ask_user` 的问答行）发生错误匹配、且两者不共享 transcript identity 时，投影逻辑会把该回复重新插入一次，导致重复渲染。

我们已核实该根因，并在上游的回归测试中复现（修复前 3 条相关用例失败，修复后全部通过）。

### 上游修复进展

修复已提交至 OpenClaw，跟踪 PR：

- openclaw#144730
- openclaw#144892

修复采用四层策略：全内容唯一匹配、要求终端证据、暂定恢复记录、以及在暂定恢复无法表示时保留后续独立 final 可见。

### 规避与升级

- **推荐**：使用 **Web 工作台**（`easel web`，默认 `http://localhost:7860`）。Web 后端从原始事件流自行渲染，不经过上述会话投影逻辑，因此**不受此问题影响**，并且提供比 CLI 更完整的会话、素材、账号、画像、内容库与发布管理能力。
- 若坚持使用 `easel chat`：待上游发布含修复的版本后，升级 OpenClaw 即可解决：

  ```bash
  npm i -g openclaw@latest
  ```

- Easel 安装的是 OpenClaw 全局 CLI（预构建产物），因此我们**不在 Easel 仓库内内置该补丁**，而是跟随上游最新版本。`easel doctor` 已加入 OpenClaw 最低版本检查（≥ 2026.6.11），版本过旧会直接提示升级。

## 第三方代理 / 兼容端点 LLM 一直超时（#9、#11）

- **影响范围**：配置第三方代理或 Anthropic/OpenAI-compatible 端点的安装。
- **表现**：`easel ping` 或小请求可能正常，但稍大、带思考的请求持续超时；部分版本上 `setup.sh` 还会报 `baseUrl: expected string, received undefined` 或 `Unrecognized key: "timeoutSeconds"`。

### 根因（已修复）

- 旧版 OpenClaw（如 2026.3.x）的 provider schema 要求 anthropic 配置**原子写入**；逐字段写入时中间态缺 `baseUrl`，整份校验失败。`setup.sh` 已改为整块一次性写入。
- 旧版本不认识 `timeoutSeconds` 字段，单次请求 600 秒空闲超时写不进去，回落到默认短超时，首个 token 稍慢即超时。该写入在老版本上已降级为尽力而为，不再中断安装。

### 建议

```bash
npm i -g openclaw@latest
git pull
bash setup.sh
```

升级后 `easel doctor` 会校验 OpenClaw ≥ 2026.6.11。不升级时安装不再报错，但请求超时受旧版默认超时限制；请确认模型名带 provider 前缀（如 `anthropic/claude-sonnet-4-6`），具体卡在哪一步可看 `easel gateway logs`。

## 对话推理强度

「设置 → 模型配置 → 对话」可保存默认推理强度；对话输入框底部将只读模型名与「推理」组合展示，可选择 `max / high / medium / low / off`。未单独选择时显示并使用默认值；旧的 minimal 映射到 low，xhigh/ultra 映射到 max，adaptive 映射到 high，转换后的会话值随下一条消息发送。会话选择保存在浏览器本地，刷新、重试时沿用；选择在下一次发送时生效，生成期间不可修改。

默认值读取 Easel 实例的 `agents.defaults.thinkingDefault`；未配置时使用 `EASEL_THINKING_LEVEL`，再回退到 `medium`。会话显式选择优先，两种对话传输均使用同一个解析结果。HTTP 接口本身不读取 `reasoning_effort`，因此通过网关 `sessions.patch` 应用强度，再发起同一会话的 HTTP 请求；CLI 使用 `--thinking`。应用失败会报错，不会静默以其他强度继续。可用档位由当前模型和网关决定，选择不支持的档位时需改选。

## 模型接口地址策略

「拉取模型」和「自测」允许用户指定任意合法 HTTP(S) 模型端点，包括本机、内网和代理 Fake-IP，不再按解析 IP 所属网段拦截。`EASEL_FAKE_IP_ORIGINS` 白名单及启动脚本的自动收集逻辑已移除。请求会携带配置的 API Key 发送到目标地址；URL 格式检查、禁止跟随重定向，以及 Web 写入来源校验仍保留。OpenClaw 独立管理网络策略：如需放开模型请求，设置每个 `models.providers.<id>.request.allowPrivateNetwork: true`；浏览器、网页抓取和定时任务 Webhook 分别设置 `browser.ssrfPolicy`、`tools.web.fetch.ssrfPolicy`、`cron.webhookSsrfPolicy` 下的 `dangerouslyAllowPrivateNetwork: true`，并移除 `blockedHostnames`。实例配置不提交 Git。

当前 OpenClaw 2026.9.8 没有覆盖所有出站请求的总开关。HTTP 输入附件的 URL 下载路径仍固定使用 `allowPrivateNetwork: false`，上述开关不覆盖它；应优先用本地上传或 Base64 输入，不能将配置放开描述成所有底层检查都已移除。

## OpenAI 兼容接口的模型切换

Web 保存模型时，按 ID 复用 `models.providers.<provider>.models` 中的定义，保留已有 `input`、`reasoning` 等字段，不再覆盖 `models[0]`。新模型追加定义，默认 `name=id`、`reasoning: true`，不写 `input`（使用 OpenClaw 默认的文字输入）、`contextWindow` 或 `maxTokens`；同时向 `agents.defaults.models` 登记空条目，已有别名、参数和运行时设置保持不变。这些默认能力是配置约定，实际支持取决于上游模型。

OpenAI 兼容接口的 UI 选择仍由现有 `.env` 的 `OPENAI_MODEL` 保存，无需新增配置文件。切换选择后需明确点击「设为主」再保存，才更新 `agents.defaults.model.primary`；仅保存选择不切换实际主模型。图片模型和备用模型引用保持不变。

对话工具栏的模型名通过网关只读查询当前会话的解析结果；新会话使用配置的主模型。设置切换、会话切换、生成状态变化和窗口重新获得焦点时刷新，并每 15 秒更新。网关不可用时，明确标记为「默认」，悬停可查看完整模型引用和状态。该展示不是每条历史回复的模型审计记录。

## 画像切换与页面导航

所有页面都可以切换左上角画像。在工作台、技能库、内容库、账号等非对话页面切换时，保留当前页面，只更新后续任务使用的画像，不创建或修改聊天会话。工作台「开始对话」和「新对话」使用当前画像创建新会话；技能执行使用页面当前选择的画像。

对话页中的空会话直接更新画像；已有消息的会话切换画像时新建会话，保留原会话的画像和历史。点击历史会话或从其他页面返回对话页时，下拉框恢复为该会话绑定的画像，包括通用模式。生成中的旧会话仍按原画像继续执行。
