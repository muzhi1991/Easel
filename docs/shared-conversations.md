# 跨浏览器共享会话

同一个 Easel 服务对应一份共享会话，无需新增用户、登录或账户系统。手机与电脑访问同一服务即可查看和继续对话。

## 存储分工

- 新建会话发送第一条消息后，列表、消息、附件引用、标题、画像绑定、推理强度、归档状态和当前任务标识保存在服务端 SQLite。未发送的空白会话是当前页面的临时草稿。
- 服务端在执行 Agent 前提交用户消息，后台任务结束后保存回复、思考和活动记录。关闭浏览器不会取消任务；另一个浏览器可重放同一个任务。页面打开、恢复到前台或每隔 5 秒刷新共享历史。
- OpenClaw、Codex 等执行引擎继续维护自己的上下文；Easel 数据库只维护界面会话，不改动执行引擎数据库。
- 旧浏览器历史继续保存在原来的 localStorage 中，标注「本地旧记录」。继续这些会话仍使用本地界面历史，不自动上传。
- 当前打开的会话、未发送文字、发布草稿、主题及首次引导标记不共享。已有画像、记忆、内容产物和平台账号仍使用原来的服务端存储。

## 迁移和兼容

只在选定的浏览器点击「迁移本浏览器旧对话 → 复制到服务端」。迁移前在该浏览器保存完整备份，成功后记录已迁移 ID；原记录不会删除。其他浏览器没有迁移标记，旧记录仍然可见。

共享会话界面 ID 使用 `shared_` 前缀，与本地旧记录分开；执行引擎和附件 inbox 使用去掉前缀后的原 ID。因此迁移保留原上下文，甚至另一浏览器存在同 ID 旧记录时也不会互相覆盖界面历史。若继续同 ID 的旧记录，它仍连接原来的 Agent 上下文，但不会自动把旧客户端界面消息同步到共享列表。

重复迁移不覆盖已经存在的共享会话。删除会话留下最小墓碑，避免旧备份重新导入时让它复活。删除共享会话不删除独立执行引擎内部的历史文件。

## 实现与维护

- SQLite 位于运行目录 `outputs/_sessions/conversations.sqlite`，由 `easel/conversations.py` 管理；备份时使用 SQLite backup API，或停止 Web 后复制数据库及其 WAL 文件。
- `/api/conversations` 提供创建、读取、单条修改和删除；`/api/conversations/import` 只供显式迁移。元数据修改和发送消息都携带版本号，过期请求返回 409，避免跨设备覆盖。
- 前端保留原 `ChatSession` 数据形状和本地兼容函数；共享接口集中在 `web/frontend/src/lib/sharedSessions.ts`。浏览器不会回写整份共享消息列表。
- Web 沿用单进程运行方式。启动时从现有任务事件日志恢复被重启打断的共享轮次，保留部分回复并提示重试。新数据库不纳入 Git。
- 验证覆盖双客户端共享、旧记录保留、幂等迁移、删除后不复活、并发版本冲突、重试截断，以及没有浏览器连接时的后台持久化。
